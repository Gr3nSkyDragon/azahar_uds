Azahar UDS Real - physical Pokemon X beacon transmission
========================================================

Purpose
-------
This patch takes the UDS beacon body already generated by Pokemon X/Azahar and
broadcasts it through the ldnd-backed monitor interface. This is the first test
of the missing emulator-to-retail discovery direction.

Files replaced
--------------
  src\core\hle\service\nwm\nwm_uds.cpp
  src\core\hle\service\nwm\nwm_uds.h
  src\core\hle\service\nwm\uds_beacon.cpp
  src\core\hle\service\nwm\uds_real\nl80211_monitor.cpp
  src\core\hle\service\nwm\uds_real\nl80211_monitor.h

No files are added to the build, so CMake does NOT need to be rerun.

Important changes
-----------------
* Generates a nonzero random UDS network id instead of leaving it at zero.
* Advertises that network id as the correct eight-character hexadecimal SSID.
* Adds standard Supported Rates, DS channel, TIM, ERP and Extended Rates tags.
* Queues Azahar's latest generated Nintendo beacon for physical transmission.
* Adds radiotap and 802.11 beacon headers using Azahar's emulated host MAC as
  both transmitter and BSSID.
* Transmits at approximately the normal 102.4 ms beacon interval.
* Uses the monitor interface's actual current channel. Once the retail 3DS is
  found, this should be its locked channel even if Azahar initially chose 11.
* Detects and suppresses Azahar's own transmitted beacon echoes so Pokemon X
  cannot list its own trainer.

Install
-------
1. Close Azahar and stop debugging in Visual Studio.
2. Extract this ZIP into the Azahar repository root, for example:

     E:\DS Emu\3DS\Azahar-UDS\azahar

3. Approve replacement of all five files listed above.
4. Do not run CMake.
5. In Visual Studio select Release and x64, then build citra_meta or the
   solution and run Azahar.

Test
----
1. Start ldnd.exe exactly as in the successful receive tests.
2. Start Pokemon X on Azahar and on the retail 3DS.
3. Leave both games on the PSS screen for at least 20 seconds.
4. Check whether each trainer appears on the other system.
5. If the emulator trainer appears on retail, select it from retail and request
   a trade. Also test the existing direction from emulator to retail.
6. Wait approximately 30 seconds, close Azahar normally, and send the complete
   azahar_log.txt along with exactly what appeared on each screen.

Expected new log messages
-------------------------
  UDS Real: BeginHostingNetwork ... networkId=0x<nonzero> ...
  UDS Real: internal beacon generation ... physicalBeaconQueued=true
  UDS Real: transmitted physical Nintendo beacon ...
  UDS Real: captured physical Nintendo beacon echo ...

The transmitter may initially report channel 11 while discovery is hopping.
After the retail beacon is found it should transmit on the locked retail
channel (channel 6 in the previous run).

Interpretation
--------------
* Transmit messages plus echo messages prove the complete Azahar -> ldnd ->
  adapter injection path is operating.
* Transmit messages without echo messages suggest the adapter/driver rejected
  or failed to loop back the injected beacon.
* Echoes with no emulator trainer on retail mean the next target is beacon
  compatibility or physical probe-response transmission.
* If the emulator trainer appears, discovery is bidirectional. Any failure
  after selecting/accepting a trade belongs to authentication, association, or
  UDS data-frame routing, which is not implemented by this patch.

You may still see a message saying that physical probe-response transmission is
not implemented. That refers specifically to probe responses; physical beacon
transmission is enabled by this build.
